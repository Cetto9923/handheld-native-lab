| 指标 | 目标 |
|---|---|

# A 组 · 分辨率与画面（RS）

## RS-001 物理输出分辨率与面板一致性

- **前置条件**：DEV-006 PASS、TS-007 PASS
- **步骤**：读取真机当前输出 surface 的实际宽高；与物理面板分辨率比对。
- **期望**：输出以真机面板为准，初始 1280×960。
- **判定口径**：PASS 条件 = 实际输出 surface == 1280×960（与 `display.physical_resolution` 一致，允许 1 px 舍入）。
- **证据产物**：`evidence/t06/resolution/output-surface.json`、截图
- **状态**：BLOCKED_DEVICE

## RS-002 16:9 内容在 4:3 面板居中 + 上下 120 px 黑边

- **前置条件**：RS-001 PASS
- **步骤**：
  1. 截图整屏。
  2. 用程序测量 3D 内容区域的像素包围盒（排除纯黑像素区），得到内容宽高与上下左右黑边。
  3. 检查内容区内是否存在被裁掉的字幕/UI。
- **期望**：内容 1280×720 居中，上下各 120 px 黑边，左右 0 px（内容宽度=面板宽度）。
- **判定口径**：
  - PASS 条件 = 内容宽 == 1280（±2 px）**且** 内容高 == 720（±2 px）
    **且** 上黑边 == 下黑边 == 120 px（±2 px）**且** 内容宽高比 == 1.7778（±0.002，证未拉伸）
    **且** 字幕/UI 完整可见。
  - 出现拉伸（比例失真）、裁切（字幕或 UI 缺失）⇒ FAIL。
  - 若黑边不是 120 px（例如为 0 而全屏拉伸）⇒ FAIL。
- **证据产物**：`evidence/t06/resolution/letterbox-<档位>.png` + `letterbox-measurement.json`（含测量方法与像素坐标）
- **状态**：BLOCKED_DEVICE

## RS-003 内部渲染档 1280×720

- **前置条件**：RS-002 PASS
- **步骤**：把内部渲染分辨率设为 1280×720；记录实际 viewport 与 render target 尺寸（不是"请求值"，是**实际生效值**）；跑固定场景。
- **期望**：内部渲染与输出合成解耦：内部 1280×720，输出 1280×960。
- **判定口径**：PASS 条件 = 实际 render target == 1280×720 **且** 输出 == 1280×960 **且** RS-002 的信箱判定仍成立。
- **证据产物**：`evidence/t06/resolution/rt-1280x720.json`（含实际 viewport/render target）、截图
- **状态**：BLOCKED_DEVICE

## RS-004 内部渲染档 960×540

- **前置条件**：RS-003 PASS
- **步骤**：同 RS-003，内部渲染 960×540。
- **判定口径**：PASS 条件 = 实际 render target == 960×540 **且** 内容仍居中、比例正确、无裁切。
**补充**：960×540 不是 16:9 整数倍缩放自 1280×720（960/1280 = 0.75，540/720 = 0.75，**是**等比，OK），
但必须确认渲染器对齐规则（像素对齐/取整）没有引入 1 px 偏移导致画面模糊或抖动。
- **证据产物**：`evidence/t06/resolution/rt-960x540.json`
- **状态**：BLOCKED_DEVICE

## RS-005 内部渲染档 854×480

- **前置条件**：RS-004 PASS
- **步骤**：同 RS-003，内部渲染 854×480。
- **判定口径**：PASS 条件 = 实际 render target == 854×480 **且** 比例/居中/无裁切判定成立。
**注意**：854×480 的宽高比 = 1.7792，与 16:9（1.7778）**不完全相等**，必须实测内容是否被轻微拉伸；
若存在可见拉伸 ⇒ 在报告中记录实际比例，并按 PROJECT.md「不拉伸」判定 FAIL 或经用户决定后放行（**不得**自行判定为可接受）。
- **证据产物**：`evidence/t06/resolution/rt-854x480.json`
- **状态**：BLOCKED_DEVICE

## RS-006 内部渲染 / 输出合成 / UI 三者分离适配

- **前置条件**：RS-003 PASS
- **步骤**：
  1. 分别设置三者的目标分辨率（UI 用不同值，例如内部 1280×720 / 输出 1280×960 / UI 1280×960）。
  2. 记录三者实际生效值与 UI 元素的实际像素尺寸。
- **期望**：三者独立可调；若游戏结构不允许 UI 独立高分辨率，记录限制，**不伪称实现**。
- **判定口径**：PASS 条件 = 三项实际生效值与设定一致 **或** 明确记录"UI 无法独立适配"的技术限制并给出证据（否则不得标 PASS）。
- **证据产物**：`evidence/t06/resolution/three-tier.json`、UI 截图
- **状态**：BLOCKED_DEVICE

## RS-007 渲染器对齐要求

# B 组 · 帧时间与性能（FT）

## FT-101 帧时间采集管线自检（先于所有性能用例）

- **前置条件**：DEV-001 PASS
- **步骤**：
  1. 采集器跑一次已知频率的合成源（例如 30 Hz 定时器驱动的空渲染），验证采样率与时间戳单调性。
  2. 实测采集开销 `overhead_ns`（空场景下开/关采集对比）。
  3. 验证 `game_frame_id` 能区分"同一帧重复呈现"（人为让面板刷新率高于渲染帧率）。
- **判定口径**：
  - PASS 条件 = 时间戳严格单调；实测开销中位数 < 1 ms；能正确标记重复呈现；
    `overhead_measured == true`。
  - **自检不过则所有 FT 用例结论无效**，必须先修采集器。
- **证据产物**：`evidence/t06/perf/pipeline-selfcheck.json`
- **状态**：BLOCKED_DEVICE

## FT-102 真实移动场景 ≥ 5 分钟

- **前置条件**：FT-101 PASS、SC-001 PASS
- **步骤**：在真实移动场景连续运行 ≥ 300 s，采集帧数据；结束后立即记录环境（温度、电池、供电、风扇）。
- **期望**：稳定 30 FPS。
- **判定口径**（按 `frametime-format.md` 的 `nearest-rank-v1`）：
  - 游玩分段：平均帧率 ≥ 29 FPS、P95 ≤ 35 ms、P99 ≤ 50 ms、> 100 ms 间隔 ≤ 1 次/5 分钟。
  - 端到端结果同时报告（含 loading）。
  - 每次 > 100 ms 的间隔必须在 `failures[]` 中定位（时刻、时长、分类、是否同点复现）。
  - **反复同点卡顿 ⇒ FAIL**，即使总次数 ≤ 1。
- **证据产物**：`evidence/t06/perf/<run_id>/frametime.json`（符合 `frametime-sample.schema.json`）、`stats.json`
- **状态**：BLOCKED_DEVICE

## FT-111 不得用重复呈现帧 / 120 Hz 刷新 / UI overlay 冒充新游戏帧

- **前置条件**：FT-101 PASS
- **步骤**：审查最终统计的 `samples[]`，确认参与分位数计算的样本 `new_game_frame == true`，
并核对 `new_game_frame_count` 与 `stats.frame_count` 的关系。
- **判定口径**：
  - PASS 条件 = 所有参与统计的样本 `new_game_frame == true` 且 `presented_content == "game"`；
    `new_game_frame == false` 的样本确实被排除但**保留在原始数据中**；
    `presented_content == "ui_overlay"` 的样本数若 > 0，说明存在 UI 叠加刷新，已正确排除。
  - 若统计里出现 `new_game_frame == false` 的样本参与计算 ⇒ **该次结论作废**，判 FAIL。
  - 面板 120 Hz 本身**不**是去重理由；去重依据只有 `game_frame_id` 重复与 `presented_content`。

## 组级出口条件

FT-101…FT-112、FT-114 全部 PASS **且** FT-109 给出最高可达固定档位，
T06 才可标记为通过。FT-113 不适用。

**所有性能结论必须来自 RG477M 真实场景。**
Mac、其他手机、空场景、菜单、系统刷新率、重复呈现帧都**不能**替代游戏帧率。
