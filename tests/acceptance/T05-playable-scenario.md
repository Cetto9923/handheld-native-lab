## SC-001 角色移动

- **前置条件**：SCPRE-1、DEV-007 PASS
- **步骤**：
  1. 进入固定起始点（截图记录起点画面）。
  2. 用固定手柄输入序列走一段路径（死循环路径，尽量含转向与斜向）。
  3. 记录全程帧数据与截图序列。
- **期望**：角色按输入移动，动画与音效同步。
- **判定口径**：
  - PASS 条件 = 位移方向与输入方向一致（逐段采样比对，允许转向延迟 ≤ 2 帧）；
    角色动画状态随运动切换（跑/走/停）；无卡死、无掉入场景外。
  - 用例失败判据：角色不动、方向反向、卡进地形、动画不切换。
- **证据产物**：`evidence/t05/movement/`（输入脚本、截图序列、帧数据、日志）
- **状态**：BLOCKED_DEVICE

## SC-002 菜单操作

- **前置条件**：SCPRE-1
- **步骤**：逐项打开主菜单与子菜单；用确认/取消/返回键遍历；记录焦点移动与状态。
- **期望**：焦点跟随输入，正确项高亮，返回逐层退出。
- **判定口径**：PASS 条件 = 焦点移动与按键一一对应且方向正确；取消键在子菜单逐层生效；无焦点丢失/无响应。
- **证据产物**：`evidence/t05/menu/`
- **状态**：BLOCKED_DEVICE

## SC-003 音频

- **前置条件**：SCPRE-1、DEV-008 PASS
- **步骤**：
  1. 录设备音频（`adb shell screenrecord` 不含音频，需另用录音或 loopback），或读取运行时的音频输出统计。
  2. 触发 BGM 与音效；记录音频设备实际采样率、缓冲与延迟。
  3. 检查是否出现持续破音、爆音、爆音循环。
- **期望**：音频正常，无持续破音。
- **判定口径**：PASS 条件 = 音频输出被实际写入设备（不是静默）；无持续破音（连续 > 1 s 的削波/失真）；音频延迟实测值有记录。
**注意**：`subsdk0` = Nintendo SDK movie（多媒体），其解码路径尚未实现时，**过场视频的音轨可能缺失** —— 该情况必须记为「未覆盖」，不得记 PASS。
- **证据产物**：`evidence/t05/audio/`
- **状态**：BLOCKED_DEVICE

## SC-004 战斗（可达范围内）

- **前置条件**：SCPRE-1
- **步骤**：
  1. 进入一个**固定**的战斗场景（记录触发路径与截图）。
  2. 执行固定输入序列（普攻、技能、移动）。
  3. 记录 HP/HP 变化、动画、音效、伤害数字，并全程采集帧数据。
- **期望**：战斗逻辑按原作规则运行。
- **判定口径**：
  - PASS 条件 = 伤害数值与原作规则一致（至少一次可核对的伤害计算）；
    动画与音效触发正确；无输入无响应；帧率统计按 FT 组口径单独出一份。
  - **战斗数值若与原作不一致 ⇒ FAIL**，不得以"看起来正常"通过。
  - 若游戏流程无法在当前实现下到达战斗 ⇒ 状态记 `BLOCKED_DEPENDENCY`，**不得**降级为 PASS。
- **证据产物**：`evidence/t05/battle/`
- **状态**：BLOCKED_DEVICE

## SC-005 过场（可达范围内）

- **前置条件**：SCPRE-1
- **步骤**：触发固定过场；记录输入到过场结束的时长、帧数据、画面序列、音频。
- **期望**：过场完整播放，逻辑时间与原作一致。
- **判定口径**：
  - PASS 条件 = 过场从头到尾完整播放且可跳过/正常结束；过场期间输入被屏蔽；
    过场时长与原作参考值一致（容差 ±5%，需有参考值来源）。
  - **禁止**用降速实现锁帧来"满足 30 FPS"（PROJECT.md 明令）。
  - 若过场由源素材视频驱动，其原生帧率必须单独记录（`segment.source_video_fps`），不与游戏帧率混算。
- **证据产物**：`evidence/t05/cutscene/`
- **状态**：BLOCKED_DEVICE

## SC-006 存读档

- **前置条件**：SCPRE-1、SCPRE-4
- **步骤**：
  1. 在固定点存档 → `adb pull` 存档文件 → 记录 SHA-256 与大小。
  2. 改变游戏状态（移动、战斗后）。
  3. 读档 → 截图确认回到存档点（位置、HP、剧情进度一致）。
  4. 重复读档 3 次，确认一致。
- **期望**：存档数据完整，读档完全恢复。
- **判定口径**：
  - PASS 条件 = 读档后位置/HP/进度三项与存档时一致；连续 3 次读档结果相同；
    存档文件在读档前后未被意外改写（除预期的写入时间戳类字段外内容一致）。
  - **存档损坏 ⇒ FAIL**（PROJECT.md 明确把存档损坏列为持续运行的失败项）。
- **证据产物**：`evidence/t05/save/`
- **状态**：BLOCKED_DEVICE

## SC-007 切后台 / 返回

- **前置条件**：SCPRE-1
- **步骤**：
  1. 在场景中按 HOME（切后台），等待 ≥ 10 s。
  2. 返回前台，观察恢复后的画面与状态。
  3. 重复 3 次。
- **期望**：恢复后画面、输入、时间线正常。
- **判定口径**：PASS 条件 = 3/3 恢复正常；恢复后位置/HP 与切后台前一致；无黑屏、无 ANR。
- **证据产物**：`evidence/t05/background/`
- **状态**：BLOCKED_DEVICE

## SC-008 休眠 / 唤醒恢复

- **前置条件**：SCPRE-1、DEV-009 PASS
- **步骤**：
  1. 场景中让设备休眠 ≥ 60 s。
  2. 唤醒并解锁。
  3. 观察恢复；重复 3 次；恢复后立刻做一次移动输入验证响应。
- **期望**：恢复正常且可继续操作。
- **判定口径**：PASS 条件 = 3/3 恢复成功；恢复后状态与休眠前一致；输入立即响应；无崩溃。
**注意**：帧时间统计跨休眠时，采集必须使用 suspend-aware 时钟或把采集拆段（见 `schema/frametime-format.md` §1）。
- **证据产物**：`evidence/t05/sleep-wake/`
- **状态**：BLOCKED_DEVICE
