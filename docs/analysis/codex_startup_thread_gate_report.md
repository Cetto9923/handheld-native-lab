# First CreateThread gate: initialization order

Static LLVM evidence, not REA. No target/helper execution, TP write or production edit. Runtime HEAD remains `f24b826b5d118b2479a476ec61aba778df26e021`. `verify_gate.py` exits 0 and checks 1109 disassembly lines against original bytes; both input hashes match the frozen source. `evidence.json` preserves exact instruction/PLT/relocation addresses and commands.

- `nninitStartup@main+352f150` branches to `13370`. First external call `1339c` is AllocateTlsSlot import59, output=`B+77740f8`, **non-null callback=`B+18c60`**. RG trap in integration `.local/device/rg477m-session1/runtime-startup.stderr` confirms these register deltas. Its current return PC `133a0` precedes the configuration writes.
- `main+133ec` loads `0x100000`; `133f4` stores it to BSS `B+77c51b8`. Startup option `-MainThreadStackSize=` at `B+6491513` can override it via `136c8/136d4`, interpreting values <=4095 as MiB. This is the game's subsequently created worker stack setting, distinct from the NPDM/native primary 64KiB stack. No nearby writer address is in DT_INIT_ARRAY. The known writer is startup, rather than evidence of a missing arbitrary C++ constructor. The candidate ADRP scan does not prove absence of all indirect stores.
- nnMain reads the same BSS slot at `352f184`; `352f188` retains its low32 bits in x19; `352f1ac` moves x19 to x4. Stack address x3 comes independently from `17c70` (returns allocation+0x1000). Six-argument call `352f1b4` is import126; return PC `352f1b8`. BSS is initially zero. The preceding successful 64KiB mapping is not proof that this zero-size worker already owns a valid stack.
- SDK six-argument export `1408d0` preserves stack pointer/size, shifts them to manager x4/x5 and priority to w6. `141d5c` only adds default **core=-2**, not a stack size. Manager `141a68` stores stack size at ThreadType+58, user argument+60, entry+68 and priority u16+44. Horizon implementation `148108` writes body to **alias+size-0x20** before native kernel creation. No default size or valid zero-size contract was established.
- Immediately before this, MapAliasStack `148018` requires the initialized StackGuardManager `144920`, a real candidate alias range and source backing. Mapper `1488c0` calls SVC4 at `17556c`; rollback callback `1489b4` reaches SVC5 at `175574`. Successful alias is stored at ThreadType+50; thread registration and stack accounting follow actual creation. Existing owned pages supply real backing, not these SDK alias/thread-manager semantics.
