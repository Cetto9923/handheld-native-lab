## 新确认的具体形态

- 24 个 CD/CF 段站点中，常量 `x0=0x238` 在 MRS 前多隔了一条无关 ADD。每处均在 `MRS+0x10` 形成地址、`+0x1c` 写至 `[sp+0x30]`；选定路径在 `+0x18c` 重载并于 `+0x190` 执行 LDR8。这解释了原相邻模式漏计的原因。24 处的原始指令均逐项校验。
- **新增真实常量 TP+0x258**，不在此前 1,440 个相邻序列的 59 种常量表内。例：MRS `+0x147a7c4 → x20`；`+0x147aac4` 读八字节，`+0x147aac8` 写八字节清零。该路径先访问 TP+0x238、TP+0x250、TP+0x260。`x20` 于 `+0x147aca0` 被重用，之后不能继续凭寄存器名字认定为 TP。
- MRS `+0x3b8d8 → x24` 先在 `+0x3b944` 把原 TP 存至 sp+0x18，再于 `+0x3b984` 重载；随后形成 0x250/0x258/0x238 三个字段地址。另有 `+0x2f00de4`、`+0x4ef93c4` 的相似形态。TP+0x250 被作为实参传给 main+0x30318；本轮未分析该 callee，不能把边界截断后声称完整覆盖。
- `+0x160b6d4 → x21` 写到 sp+0x2a0；原寄存器随后被覆盖，`+0x160b890` 重载后选定路径 `+0x160b9f4` 读 TP+0x238。栈暂存值的全部到达定义与跨调用别名仍未证明。
- `+0x32221bc → x10` 后立即形成 `x27=TP+x8`、`x8=TP+x0`，稍后 `x21=TP+x9`。有两条条件边从 `+0x3222138/+0x322213c` 进入 `+0x3222194`，对应可见常量 0x258/0x238/0x250；其他可见控制流会重用 x8/x9，且存在反向跳转。本报告不推断全部汇入值，因此保留动态表达式与未知范围，不标 in-bounds。

从 TP 字段加载出来的指针再访问 `[pointer+0]` 或 `[pointer+0x30]` 属于被指向对象的操作，不能写成 TP header 的操作。TP 的值存到 `[sp+8]` 也不是访问 TP+8。

## 对原生 TP 适配的影响

只替换相邻 `MRS x8; LDR` 模式不够：本轮目标寄存器包含 x8/x9/x10/x20/x21/x24/x26/x28，TP 会经栈逃逸、重载、跨块复用和向 callee 传参。模板镜像复制组件本身不能解决这些使用。

最小后续研究是先闭合 +0x32221bc 的 CFG 汇入与寄存器到达定义，再追踪明确的调用边界 +0x30318，以及 TP 栈暂存的别名/覆盖范围。当前信息支持设计保留寄存器与状态的访问适配边界；尚不足以安全地批量改写所有 MRS、绑定 Android 宿主 pthread 或放行 SDK 初始化 gate。
